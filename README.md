# 羽球记分｜羽毛球比赛技术统计

一个面向日常练习和业余比赛的手机优先羽毛球记录工具。它把比赛中的每一分、使用的技术动作和失分原因记下来，赛后按场次、对手和技术维度汇总，帮助球员发现自己的得失分模式，也为研究不同对手的打法提供可回看的记录。

项目采用纯 HTML、CSS 和 JavaScript，不依赖账号、后端、数据库或第三方运行库。可以作为网页使用，也可以安装到手机桌面；首次联网打开后会缓存应用文件，之后可离线记录。训练记录保存在当前设备的浏览器中，不会自动上传或跨设备同步。

## 适合谁

- 想在训练或业余比赛中快速记录比分和逐分技术信息的球员。
- 想回顾主要得分手段、常见失分原因和击球落点的个人训练者。
- 想比较不同对手的比赛表现，并记录对方关键技术特点的球员或陪练。
- 想导出结构化比赛数据，再交给大模型辅助总结的人。

## 功能

- 正规比赛：21 分制或 15 分制，三局两胜。
- 自由比赛：5、7、11、15 或 21 分制，单局定胜负。
- 按日期建立训练场次；同一场训练可保存多场对局并按对手汇总。
- 逐分记录我方得分或失分、我方技术动作、失分原因；可选记对方关键技术和球场落点。
- 支持撤销、赛后复盘，以及 Markdown 分析稿和 JSON 原始数据导出。
- Android 和 iPhone 均可通过浏览器添加到主屏幕，无需 APK 或应用商店。

## 隐私与数据

比赛记录只保存在使用者当前设备和浏览器的本地存储中。GitHub Pages 只托管公开的应用程序文件；访问者的比赛内容不会写入 GitHub。清除浏览器网站数据可能会删除本机记录，建议定期导出 JSON 备份。当前版本不提供记录导入或自动云同步。

## 计分模式

- **正规比赛**：21 分或 15 分，均采用三局两胜。21 分制在 20 平后需领先 2 分，30 分封顶；15 分制在 14 平后需领先 2 分，21 分封顶。
- **自由比赛**：5、7、11、15 或 21 分，单局定胜负；先到目标分获胜，不加分。

新建训练场次时填写日期、我方名称、第一场对手和计分规则。场次中可连续添加不同对手的比赛；同一对手的多场比赛会单独保存，并在场次汇总中合并展示该对手的战绩。BWF 批准的新 3×15 赛制计划于 2027 年 1 月 4 日起实施；具体赛事安排以组织方为准，App 在切换前仍保留 21 分制作为默认值。

## 启动

开发预览时可在本目录运行：

```powershell
python -m http.server 8000
```

再打开 `http://localhost:8000`。停止本地静态文件服务时，在启动它的终端按 `Ctrl+C`。手机安装需要把本目录作为静态网站发布到一个可访问的 HTTPS 地址；`localhost` 和电脑上的本地预览地址不能直接作为手机安装地址。

## 安装到手机

1. 将本目录发布到支持 HTTPS 的静态网站托管服务，取得网站地址。只需静态文件托管，不需要服务器程序或数据库。
2. Android：用 Chrome 打开该 HTTPS 地址，选择“安装应用”或“添加到主屏幕”。
3. iPhone：用 Safari 打开该 HTTPS 地址，点“分享”→“添加到主屏幕”。
4. 首次成功打开后，应用文件会缓存在手机上；之后可以从桌面图标打开并离线记录。

### GitHub Pages 发布步骤

1. 在 GitHub 新建仓库，把本目录里的应用文件上传到仓库根目录（至少包括 `index.html`、`app.js`、`core.js`、`styles.css`、`manifest.webmanifest`、`sw.js` 和 `icon.svg`）。
2. 打开仓库的 **Settings → Pages**。
3. 在 **Build and deployment** 下选择 **Deploy from a branch**，分支选 `main`，目录选 `/(root)`，点 **Save**。
4. 等待 Pages 发布完成，打开 GitHub Pages 显示的 `https://<账号名>.github.io/<仓库名>/` 地址。

GitHub Free 个人账号需要使用公开仓库才能发布 Pages；网站本身也会公开访问。公开的是网页程序代码，不包含手机里保存的比赛记录。比赛记录仍只保存在打开该网址的设备浏览器中。

记录保存在每台手机自己的浏览器存储中，不会自动与电脑或其他手机同步。部署地址固定后，尽量一直使用同一个地址打开，避免浏览器把不同地址当作不同应用数据空间。

## 现场记录与回看

1. 输入训练日期、我方名称、场次名称和第一场对手并开始记录。
2. 选择我方得分或失分，再依次选择我方最后执行的技术和主要原因。
3. 一分保存后，可点九宫格补填我方击球位置；也可跳过或直接开始下一分。
4. 赢得一场比赛后可添加下一场比赛、切换对手和计分规则，或结束训练场次。
5. 首页“训练记录”可按日期回看各场次、逐场结果和按对手汇总。

训练记录保存在本机浏览器 `localStorage`。清除该浏览器数据会删除记录；目前不提供云同步。场次汇总支持导出 Markdown（适合直接提交给大模型）和 JSON（包含完整逐分原始数据），建议定期保存导出文件作为备份。旧版最近一场比赛记录会在首次打开时迁移到训练记录。

## 失分前置原因补记

失分后的“补记上一分资料”增加“被调动失位”和“被动回球过浅”，按观察到的先后顺序选择，允许多选，再次点击取消。比赛结束后的最后一分也可补记。

每个回合保留原 `reason`（主要原因 / 终结结果），新增可选的 `lossCauses` 有序数组。例如：`["被调动失位", "被动回球过浅"]` 关联该回合的“被对方进攻击穿”。未记录时为 `null`，旧回合缺失该字段也保持未知；不自动推断前置原因。

报告分别展示前置原因次数、补记覆盖率和观察链条。JSON 与 Markdown 导出保留这些资料，供后续 AI 区分终结结果与前置问题。观察链条不等同于已验证的因果结论，多选比例之和可能超过 100%。
